# 横屏渲染优化 + 朝向/抖动算法切换

## 问题与目标
1. **横屏照片被压扁**：`/sim_render` 返回的横屏渲染图（800×480）被 `drawImage(img,0,0,480,800)` 拉伸进固定的 480×800 竖屏 canvas，导致横版照片严重变形。
2. **朝向不可切换**：`render_image(meta)` 内部用 `compute_render_orientation(img_w,img_h)` 自动判定，无法手动强制横/竖屏预览。
3. **抖动算法单一**：仅有 Floyd–Steinberg 四色抖动（`apply_four_color_dither`），无法对比不同算法。

## 修改方案

### 一、`render_daily_photo.py`：让 `render_image` 支持朝向覆盖
当前 `render_image(item)` 在第 867 行硬编码调用 `compute_render_orientation(img_w, img_h)` 决定朝向。

**改动**：给 `render_image` 增加可选参数 `force_orientation: str = "auto"`（取值 `auto`/`portrait`/`landscape`）：
- `"auto"`（默认）：保持现有逻辑 `compute_render_orientation(img_w, img_h)`，**完全向后兼容**（ESP32 下载接口 `main()` 等所有现有调用方零影响）。
- `"portrait"`：跳过第 867 行的横屏分支，强制走竖屏管线。
- `"landscape"`：跳过自动判定，直接 `return render_image_landscape(item, img)`。

新增三个抖动函数（紧跟现有 `apply_four_color_dither` 之后，第 1345 行附近），全部量化到现有四色调色板（黑/白/红/黄），复用 `nearest_palette_color`：

- `apply_atkinson_dither(img)`：Atkinson 误差扩散，误差的 1/8 扩散给 6 个邻居（右、右右、下、右下、左下、下下），对比度高、细节柔和。
- `apply_bayer_dither(img)`：4×4 Bayer 有序抖动，规则点阵无噪点，速度快。
- `apply_no_dither(img)`：无抖动，每像素直接吸附到最近调色板色（最近色量化），色块分明无渐变。

再加一个分发函数 `apply_dither(img, algo="floyd_steinberg")`，按 `algo` 取值（`floyd_steinberg`/`atkinson`/`bayer`/`none`）调用对应函数，未知值回退到 `floyd_steinberg`。

### 二、`server.py`：`/sim_render` 接收朝向与算法参数
`/sim_render`（第 2254 行）当前只接收 `img` 参数。

**改动**：增加两个可选 query 参数：
- `orient`：`auto`/`portrait`/`landscape`，默认 `auto`。传给 `rdp.render_image(meta, force_orientation=orient)`。
- `dither`：`floyd_steinberg`/`atkinson`/`bayer`/`none`，默认 `floyd_steinberg`。调用改为 `rdp.apply_dither(img, dither)`。

### 三、`server.py`：`build_simulator_html` 前端 UI + canvas 自适应
**UI 控件**（改造第 1683 行的 `.controls` 区）：
- 朝向切换：一组三选一按钮组 —— `自动` / `竖屏` / `横屏`（默认"自动"高亮）。
- 抖动切换：一组四选一按钮组 —— `Floyd-Steinberg` / `Atkinson` / `Bayer有序` / `无抖动`（默认 FS 高亮）。
- 保留原有 `同一天换一张` 按钮。
- 按钮用现有 `.controls button` 样式，选中态加 `.active` 高亮类（新增 `.controls button.active` CSS：accent 背景 + 边框）。

**canvas 朝向自适应**：`drawPreview(photo)`（第 2017 行）改造：
- 增加 `currentOrient`、`currentDither` 两个模块级状态变量。
- 根据**实际返回的渲染图尺寸**动态设置 canvas：`img.onload` 里读取 `img.naturalWidth/naturalHeight`，据此设 `canvas.width/height`，再 `drawImage(img,0,0,canvas.width,canvas.height)`。这样竖屏图→480×800 canvas、横屏图→800×480 canvas，无拉伸。
- 预览图 URL 改为：`'/sim_render?img=...&orient='+currentOrient+'&dither='+currentDither`。
- 切换朝向/抖动按钮 → 更新状态变量 + 重新调用 `drawPreview(currentPhoto)`。

**状态记忆**：朝向/抖动选择用 `localStorage` 持久化，刷新页面后保持上次选择。

| 文件 | 改动 |

| `render_daily_photo.py` | `render_image` 加 `force_orientation` 参数；新增 3 个抖动函数 + `apply_dither` 分发器 |
| `server.py` | `/sim_render` 加 `orient`/`dither` 参数；`build_simulator_html` 加朝向/抖动切换 UI、canvas 自适应、状态变量与 localStorage |

## 兼容性
- `render_image(item)` 不传第二参数时行为不变，ESP32 下载接口（`main()`、BIN 生成）零影响。
- `/sim_render` 不传新参数时默认 `auto` + `floyd_steinberg`，与现状一致。
- 重启 `inktime-server.service` 生效后即可在浏览器验证。
