## 方案：server 常驻 + 服务器授时（解决 NTP 失败导致设备沉睡）

### 背景与根因
ESP32 凌晨定时唤醒后若公网 NTP 失败，`sleepUntilNextSchedule` 会直接睡 24h（`ink-display-wifi-epd.ino:1899-1902`），错过当天刷新点，且每次醒来 NTP 再失败就继续沉睡。公网 NTP（pool.ntp.org 等）易因路由器/运营商抖动失败。

### 核心思路（你的提议）
设备每天都要连局域网 server 拉照片，让 server 顺便授时。server（树莓派）时间准确、常驻在线，是比公网 NTP 更可靠的时间源。授时走局域网，不依赖外网。

### 改动清单（4 处）

#### 1. server.py：新增授时接口
新增 `GET /static/inktime/<key>/time`，返回当前 Unix epoch（纯数字字符串，如 `1786300000`）。复用现有 `<key>` 校验（`key != DOWNLOAD_KEY` 则 404），与其他 ESP32 接口同前缀、同鉴权。
```python
@app.get("/static/inktime/<key>/time")
def esp_time(key: str):
    if key != DOWNLOAD_KEY:
        abort(404)
    return str(int(time.time()))
```
（`time` 已 import，无需新增依赖）

#### 2. ESP32 固件：syncTime 增加服务器授时回退
改造 `syncTime()`（ink-display-wifi-epd.ino:1347），新增三层降级：
1. **先试公网 NTP**（保留现有逻辑，多数情况成功）
2. **NTP 失败 → 拉 server `/time` 接口**，用 `settimeofday()` 设系统时钟（新增 `fetchServerTime()` 函数，参照现有 `fetchPhotoOrientation` 的 HTTPClient 写法）
3. **都失败 → 返回 false**（setup 里会重试一次，仍失败才走 hasTime=false 兜底）

新增函数 `fetchServerTime(cfg)`：
```cpp
// 从服务器 /time 接口拉 Unix epoch，用 settimeofday 设系统时钟
static bool fetchServerTime(const Config &cfg) {
  String url = buildPhotoUrl(cfg, "");  // 复用前缀 → .../photo_  不对
  // 需单独构造: "http://<host>/static/inktime/<key>/time"
  ...
  HTTPClient http; http.begin(url); http.setTimeout(8000);
  if (http.GET() != HTTP_CODE_OK) return false;
  String body = http.getString(); http.end();
  time_t epoch = (time_t)body.toInt();
  if (epoch <= 0) return false;
  struct timeval tv = { .tv_sec = epoch, .tv_usec = 0 };
  settimeofday(&tv, nullptr);
  // 设时区（configTime 已设过 tz，settimeofday 后需重应用 tz）
  return true;
}
```
**注意**：`DAILY_PHOTO_PATH_PREFIX` 是 `/static/inktime/andyhome0203/photo_`（含 photo_ 后缀），授时接口是 `/static/inktime/andyhome0203/time`，不能直接复用 `buildPhotoUrl`。需新增一个构造 time URL 的辅助，或把前缀拆成 base+suffix。

#### 3. systemd：server 常驻服务
新建 `/etc/systemd/system/inktime-server.service`（需 sudo 安装）：
```ini
[Unit]
Description=InkTime photo server (ESP32 fetch)
After=network-online.target

[Service]
Type=simple
User=andy
WorkingDirectory=/home/andy/inktime
ExecStart=/home/andy/inktime/venv/bin/python3 /home/andy/inktime/server.py
Restart=on-failure
RestartSec=5
StandardOutput=append:/home/andy/inktime/logs/server.log
StandardError=append:/home/andy/inktime/logs/server.log

[Install]
WantedBy=multi-user.target
```
- `systemctl enable --now inktime-server` 开机自启+立即启动
- 崩溃自动重启（Restart=on-failure）
- server.py 现有的 `/shutdown` 接口需评估：常驻后不应被 inktime_daily.sh 关掉，需从脚本里移除 shutdown 调用（见下条）

#### 4. cron / inktime_daily.sh：简化
`inktime_daily.sh` 的 Step 3（启动 server、等拉取、shutdown）整段**删除**——server 已常驻，不需要再起停。脚本简化为：
- Step 1：渲染（保留）
- Step 2：BLE 推送（保留，按开关）
- ~~Step 3：起/等/关 server~~（删除）
- 新增 Step 3：server 健康检查（curl 一下 `/time` 确认存活，失败则告警）

cron 时间不再受 server 窗口约束，可保持 04:50（纯渲染时间）。设备 refresh_hour=5，靠服务器授时准时唤醒拉取，server 一直在，窗口问题彻底消失。

`inktime_check.sh`（06:00 重试）也可简化：不再重跑 inktime_daily.sh，只检查 server 存活 + 当天是否有拉取记录。
