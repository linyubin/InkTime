# 0002 — 版式从"一版式一函数"迁移为声明式样式数据 + 通用渲染器

## 状态

accepted（2026-09-24）

## 决策

在册 12 款版式（`render_layouts.py` 的 P/L 函数）转写为声明式样式数据（JSON），
由一个通用解释渲染器按数据绘制（复刻 `_glass`/`_scrim`/`_seal`/`_draw_dark` 等绘制
原语的语义）；新建的 HTML 样式编辑器与 Python 渲染管线读写、消费**同一份**样式
文件。迁移验收标准：新旧两套实现对每款版式 × 每张压力测试照片逐像素对比全部
通过后，旧函数退役；`layout_strategy` 的选型打分与硬否决按版式 ID 索引，不受
实现形式影响，保持不动。

编辑器预览必须与 Pillow 输出高保真一致（同一字体文件、同一坐标系、同样的渐变/
圆角/透明度语义），这是选择"HTML 编辑器 + 双端渲染"路线的既定前提。

## 被否决的备选

- **双轨并存**（老 12 款留函数、新样式走 JSON）："加载已有样式编辑再保存"对老款
  永远差一步临时转写，且两条渲染路径长期共存、验证负担翻倍。
- **编辑器导出 Python 函数**（代码生成）：生成物不可人工维护、diff 噪音大，样式
  数据与渲染语义仍然两处漂移。

## 后果

- Pillow 与浏览器两套渲染必须长期保持视觉一致：修改任一绘制原语（如 `_scrim`
  渐变语义）时两边同步改，以像素对比脚本把关。
- 样式文件成为版式的唯一事实来源；版本与回滚交给 git。
- 节日模板（`holiday_render.py` 的 9 套）是否随后数据化，另行决策（本期范围外）。
