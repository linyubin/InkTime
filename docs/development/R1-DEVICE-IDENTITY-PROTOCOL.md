# R1/PR-02 — ESP32 注册身份与所有权协议 v1（隔离设计，不启用）

## 目标与当前边界

当前设备自动注册路径是 `POST /api/device_register/<download-key>`，服务端只保存一个 `endpoint.json`。下载密钥为多个设备共用的**内容访问凭证**，不是设备身份；可选来源 IP 白名单只能缓解异源覆盖。管理员手动覆盖和共享密钥的最后写入者生效问题仍然存在。

本工作包只新增 `device_registration_identity.py` 的**纯函数协议验证器**和隔离测试。**没有接入 server.py，没有新增环境变量，没有改变 endpoint.json、HTTP 接口、固件或默认行为。当前运行中的设备注册仍不具备独立设备身份认证。** 不得据此将 R1 Gate 标为通过。

## 提议的单设备所有权协议

1. 管理员在隔离 provisioning 阶段为设备分配唯一 `device_id`（小写 ASCII 字母/数字开头，后续允许 `a-z0-9_-`，总长度 1–32），以及通过安全随机数生成的**每设备独立 32 字节或以上密钥**。密钥只在设备受保护的持久存储和服务端受保护的配置中保存，不写入 Git、日志、URL 或 endpoint.json。不能复用下载密钥或 Wi-Fi 密码。
2. 服务端**显式配置**唯一预期的 owner ID 和对应密钥；不能由首次请求自动认领所有权。设备发送原有 JSON body 原始字节，同时在后续固件版本中附带 `X-InkTime-Device-ID`、`X-InkTime-Counter`、`X-InkTime-Signature`。签名为小写 64 字符十六进制 HMAC-SHA256。
3. 签名消息按 UTF-8/ASCII 拼接，最后有一个换行符：`inktime-device-register-v1\nPOST\n/api/device_register\n<device_id>\n<decimal_counter>\n<sha256(raw_body).hex()>\n`。它绑定方法、逻辑路由、设备 ID、单调计数器与**原始 HTTP body**。URL 中旧版下载密钥不是签名密钥，也不参与签名消息。任何 JSON 字节改动都使签名失效。
4. 计数器必须为规范正十进制字符串（无前导零），范围 1…2^63-1。服务端需要在**同一个 endpoint POSIX 锁内**检查 `counter > durable_last_counter`、验证 HMAC、校验端点，然后将 owner ID、计数器和端点一起原子持久化；**只有完成文件及目录 fsync、锁和 inode 最终验证后才能 HTTP 200**。必须设计对失败 ACK 后重试的处理：设备应使用新的递增计数器重新签名；不允许仅靠内存计数器防重放。计数器回退、设备 NVS 损坏或丢失时拒绝自动注册，须人工重新配对，不得静默重置。
5. 签名和设备 ID 的校验必须使用常量时间比较；非法 ID、签名、密钥、计数器统一拒绝，不能输出秘密到日志。对外响应避免泄漏哪个校验阶段失败。旧版下载密钥仍需独立验证；HMAC 不替代 HTTPS/局域网隔离或管理端 CSRF。

## 迁移、兼容与撤销策略（尚未实现）

- **默认旧行为保持**：本次纯函数模块不参与请求处理。未来应先实现独立 staging 配置及只读观测，再在设备固件完成 NVS 安全写入、计数器更新、重试与断电恢复后，按单设备灰度启用“必须签名”模式。
- **禁止降级**：一旦设备进入强制签名模式，缺少签名的旧固件不能静默回退为下载密钥注册；回滚只能由管理员离线显式批准，且需记录安全影响。
- **所有权转移**：管理员离线授权清除旧 owner/counter 并重新配对新设备，不能通过网络请求自动转移；旧设备凭证必须撤销。多设备管理需要从单一 endpoint.json 升级为独立设备记录及选定活动设备，不能将本方案视为多设备支持。
- **轮换**：新旧设备密钥仅允许短期、显式双槽迁移，旧密钥撤销必须可审计；不要把设备密钥、下载密钥与 AP 密码混用。
- **网络前提**：HMAC 保护消息完整性与持有密钥证明，但不加密 IP/内容，也不能抵御已泄露的设备密钥、被控制的设备或可阻断请求的攻击者。

## 本工作包测试和验收限制

隔离标准库测试覆盖正确签名、body 篡改、错误密钥、非 owner、计数器重放/回退、非法编码/格式、弱密钥及输入大小。测试**不证明** endpoint 原子提交、HTTP 集成、设备 NVS 计数器、网络重试或硬件安全。

后续工作包：在受控配置下接入 Flask 注册路由，设计持久化 owner/counter 与原子事务，加入跨进程竞争、fsync 失败/重试、旧固件拒绝和撤销的故障注入测试；随后做真实 NAS、HTTPS 浏览器、ESP32 编译和真机验收及人工签核。不得合并或部署。

## 回滚与风险

本包只增加两个源/测试文件和本文档；开发分支可逆序撤销对应提交并重跑 CI，现有设备行为不受影响。未来若将协议接入生产，不能简单回滚为允许无签名注册，因为会恢复共享密钥覆盖风险；必须制定带有人工授权的迁移/撤销流程。

**外部验证状态：** 真实 NAS/NFS/SMB、HTTPS 浏览器/CSRF、Docker/systemd、ESP32 编译/NVS/真机及人工签核均未验证。**R1 Gate OPEN；R2/R3 不得宣称通过。**


## 2026-10-30 — 隔离持久化事务（R1/PR-02，仍未启用）

新增 device_registration_storage.py，以 endpoint.json 为**单一原子记录**，采用现有 .endpoint.json.lock 跨进程锁、固定目录 fd、拒绝符号链接/硬链接、临时文件 0600、文件和目录 fsync、原子 os.replace 及最终 inode 检查。**未修改 server.py、管理员接口或 ESP32；这不是已启用的身份认证。**

- provision_registration_owner(path, owner_id=...) 只供**离线管理员**调用，不允许从 HTTP 路由调用。仅当 endpoint.json 完全不存在时，创建 {_identity_version:1, _device_id:<id>, _last_counter:0, ip:null, port:null, alwayson:false, ts:""}。已有旧格式/损坏/不安全文件一律拒绝，不自动认领、不自动清空计数器。初始化状态没有可用 IP，现有读取端会视为离线。
- commit_verified_registration(...) 在**同一个 endpoint 锁**内读取严格格式的既有状态、比对预配置 owner、验证 HMAC 与严格递增计数器，再将 owner、计数器、从真实 TCP 对端获取的 IP、由已签名 body 得到的端口/alwayson 一起原子发布。请求 body 仅允许 port（可省略，默认 80）和布尔 alwayson（必填），重复 JSON 字段拒绝；peer_ip 必须由可信服务端从 socket 获取，不能取 XFF 或 body。
- **禁止隐式重新配对：** 缺失、损坏、旧版或 owner 不匹配的状态均拒绝网络注册。计数器丢失时只能走独立的离线人工恢复/密钥轮换流程；不能直接复用旧凭证将计数器重置为 0。未来上线前必须保证管理员手动设置及旧版自动注册不能覆盖身份字段，也不能在强制认证模式下降级。
- **ACK 语义：** 函数正常返回后才允许 HTTP 200。写入前 fsync 失败保留旧记录；rename 后目录 fsync 或锁最终校验失败可能使新计数器已可见但未 ACK。设备重试**必须使用更大的计数器并重新签名**，不能重放相同计数器。真实 NAS 的掉电持久性仍待验证。
- **限制：** 目前没有配置入口、Flask 路由集成、密钥供应/轮换/撤销、管理员手动修改的认证模式门禁、ESP32 NVS/重试实现；现有下载密钥和可选 IP 白名单行为完全不变。此记录是单设备方案，不是多设备注册表。flock 只约束遵守协议的进程，外部写入者、NAS 锁语义和文件系统故障仍是风险。

隔离测试包含离线 provisioning、正常递增、重放/回退、身份/签名/body 篡改、旧文件拒绝、损坏/重复字段、锁争用、符号链接/硬链接、前后 fsync 故障和 ACK 丢失后的新计数器重试。**这些仅是 Linux/CI 测试，不是 NAS、HTTPS 浏览器、Docker/systemd 或真机验收。**

回滚只允许在开发分支撤销本次隔离存储模块、测试和 CI 文档提交并重新运行 CI；不得用简单回退到共享密钥注册作为未来生产环境的安全回滚。R1 Gate 继续 OPEN，R2/R3 不得宣称验收通过。
