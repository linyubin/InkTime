# R1 / PR-02 — ESP32 Wi-Fi 凭据去硬编码迁移指南（仅源码阶段）

## 范围与已实施行为

`esp32/ink-display-wifi-epd/ink-display-wifi-epd.ino` 不再携带内置备用 Wi-Fi SSID/密码，也不会在启动时把备用网络自动写入 NVS。保留 3 个 NVS 配置槽位：组 0 使用旧键 `ssid/pass`，组 1/2 使用 `ssid1/pass1` 和 `ssid2/pass2`。既有保存、网络扫描、AP 配网入口不变。

**这只是开发分支的源码修改。未构建固件、未烧录、未连接真实 ESP32，也未验证真实 NVS 或网络行为。** 当前运行中的设备不会因 GitHub 代码变更而自动更新或删除凭据。

## 预期兼容性

| 场景 | 预期源码路径 | 待验证 |
|---|---|---|
| 旧设备 NVS 已有有效 Wi-Fi | `loadConfig` 读取原有 3 个槽位，继续扫描并连接 | 真机读取、重启与深睡 |
| 全新设备 NVS 为空 | `g_cfg.valid == false`，进入 `startConfigPortal()` | 首次配网、屏幕提示 |
| 恢复出厂（按住 BOOT） | `clearConfigNVS()` 清空 `dashcfg`；不再自动补回旧网络 | 真机恢复与重新配网 |
| 旧版曾自动写入的备用网络 | **不会自动清除**；仍作为普通 NVS 槽位被读取，必须人工清理 | 清理与轮换 |

## 部署前人工操作清单（本轮未执行）

1. **立即将公开历史中的 Wi-Fi 密码视为泄露**：在路由器/AP 端轮换该网络密码，必要时迁移到隔离的设备专用 SSID/VLAN。删除源码中的明文不能抹去 Git 历史、旧固件镜像或设备 NVS。
2. 在受控网络中核对各设备现有 NVS 配置，使用设备 `/network` 页面移除曾自动写入的备用网络槽位（空 SSID = 删除），并录入轮换后的密码；不应在未确认新网络可连接前远程清空所有槽位。
3. 保留原始固件镜像、NVS 配置快照与设备连接信息。首次刷入新固件必须在可现场恢复的条件下进行，验证现有配置不丢失、重启/深睡后可重连、首次配网与 BOOT 恢复路径正常。
4. 检查服务器下载路径密钥、设备 AP 配网口令、设备管理 HTTP 接口的访问边界。**当前固件仍存在固定 AP 配网口令与源码中的下载路径密钥**；本工作包没有解决这些独立风险，不能据此宣布 PR-02 全部通过。
5. 若验证失败，在隔离环境恢复先前已知可用固件与 NVS 快照；**旧固件可能再次自动注入泄露的备用网络**，因此仅允许在受控测试环境短期回退，并优先修复或隔离该风险。

## 自动化测试与验收限制

`tests/test_firmware_wifi_credentials.py` 仅检查源码不再包含内置备用凭据/注入函数、NVS 键保持兼容、空配置进入 AP 的代码路径、恢复出厂与配置页面入口仍存在。这些是**静态回归约束，不是 Arduino 编译或真机测试**。
